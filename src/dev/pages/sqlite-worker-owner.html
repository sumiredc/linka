Sharing one SQLite database across tabs

SQLite compiled to WebAssembly can keep its database file in the origin private file system (OPFS). The fast path goes through a synchronous access handle, and that handle locks the file: a second tab that opens the same database fails.

One owner, many clients

Instead of letting every tab open the file, open the database in a single dedicated worker and send every tab's queries to it as messages. Use a named Web Lock to decide which tab starts the worker; when that tab closes, the lock is released and the next tab in the queue takes over.

A file, not a memory image

Because the database lives in a file on OPFS, SQLite reads only the pages a query needs. The dataset does not have to fit into WebAssembly memory, which tops out at 4GB.

What it costs

Every query now crosses a message boundary, so results are copied with the structured clone algorithm. Batch small queries into one message where you can.
